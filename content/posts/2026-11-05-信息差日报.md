## 🧊 冷知识

### 为什么一分钟是 60 秒

我们用 60 秒记一分钟、60 分钟记一小时，这套规则已经沿用了四千多年，却很少有人问一句：为什么偏偏是 60，而不是更顺手的 100？

答案藏在古美索不达米亚人的手指上。苏美尔人和巴比伦人用的是六十进制：用一只手的大拇指去点另一只手的四根手指——每根手指三节指骨，一共 12 节；再配合另一只手的 5 根手指做"进位"，12 × 5 正好是 60。这种"用手数到 60"的办法，能表示的数是十进制数到 10 的六倍。

更关键的是 60 这个数本身好拆：它能被 1、2、3、4、5、6、10、12、15、20、30、60 整除，是 100 之前拥有最多因子的数。古巴比伦的天文学家就靠它把圆切成 360 度、把一天分成 24 小时，再往下分成 60 分、60 秒。这套刻度后来被希腊人、阿拉伯人一路继承，最后固定成了今天钟表的样子。你手腕上那块表的每一次跳动，其实是一个四千年前用手指关节数出来的约定。

### Hira

> [!tip] 简介
> 一个免费的求职 agent：24/7 自动找机会、自动投递，只在 iMessage 和 Muse 上。

求职里最耗人的不是"找不到工作"，而是把同一份简历拆开、填表、点提交这件事重复一百遍。Hira 的切入点就是自动化掉这层：一个专属的个人 agent，全天候帮你搜职位、自动投递。目前的入口是 iMessage 和 Muse——把 agent 塞进你已经在用的聊天工具里，而不是再让你装一个 app。

自动求职赛道这两年一直在起，Simplify、LazyApply、AI Apply 都在这条线上。Hira 的差异是"完全免费"加"对话式入口"，门槛几乎为零。但免费也意味着它的商业模式和可持续性还没摊开讲，自动投递的质量（会不会乱投、会不会踩到招聘系统的反垃圾机制）也还没经过大规模检验。

对海投型求职者，省下的是大量机械劳动；对目标明确、想精细打磨每一份申请的人，自动投递反而可能帮倒忙。创始人明确说是免费，所以现在试的成本很低，但最好盯着它到底帮你投了什么。

### OpenMail

> [!example] 简介
> 给每个 AI agent 一个自己的邮箱和独立的发送信誉，一次 API 调用搞定。

agent 越来越多地要"自己注册工具、给真人发邮件"，但邮箱是为人类设计的——于是 agent 只能借用某个人的 Gmail，共享密码、共享信誉，一个 agent 干蠢事，同地址的其他 agent 一起被拉黑。OpenMail 解的就是这个：每个 agent 一个独立 inbox，挂在你自己的域名下，收信以 JSON webhook 进来、附件直接解析成模型能读的文本，坏一个只伤它自己。

这条"agent 的邮件层"最近冒头很快，AgentMail、Mailtrap、Nylas 都在做。OpenMail 的差异在细节：每个 inbox 有独立的发送信誉（SPF、DKIM、DMARC 自动配好），免费档给 3 个 inbox、每月 3000 封，付费 $7+/月/个。创始团队在维尔纽斯，数据留在欧盟。

对正在把 agent 交付给客户、或者让 agent 处理真实业务的团队，这个比"再给 agent 配一个 Gmail"干净得多。边界也清楚：它管的是"收发邮件"这层基础设施，不帮你管 agent 该说什么话——内容质量还得你自己盯。

### Render Sandboxes

> [!success] 简介
> 给每个 agent 一台亚秒级启动的隔离 Linux 电脑，跑任意 harness。

"每个 agent 都需要一台电脑"——Satya Nadella 这句话正在变成基础设施层的共识。Render 这次上 PH 的 Sandboxes，就是把这句话落地：每个 agent 拿到一台隔离的 Linux 机器，亚秒级启动，能跑 Claude Code 或任意 harness。和 LangSmith Sandboxes（微虚拟机）同一条赛道。

这里的关键分歧是"容器够不够"。Render 自己的文章说得很白：容器适合跑已知的、被审过的代码，不适合装任意依赖、跑模型生成的脚本的 agent——而且容器和宿主机共享内核，一个内核漏洞就能打穿。所以 Sandboxes 走的是隔离更硬的路线，同时又把"亚秒启动"这个 serverless 的爽点和"有状态、能装依赖、能接着上次继续"这台完整机器的爽点揉在一起。

对正在让 agent 写代码、跑代码的团队，这是"别让 agent 直接碰你的基础设施"这句安全老话的工程化答案。边界：它是 Render 生态内的一环，你得在 Render 上跑工作流才能吃到最顺的体验；自建微 VM 沙箱的复杂度和成本，也不是所有人都愿意背。

## 🧠 Big Think

### 懂得越多，越难说服人

有一个实验让我印象很深：一个人在心里默唱一首歌，然后在桌上敲出它的节奏，让另一个人猜是什么歌。敲的人觉得自己的"敲击"清清楚楚，可对方听到的只是一串无意义的"哒哒哒"。这个实验有个名字，叫"知识的诅咒"——一旦你知道了旋律，就再也无法假装自己不知道它，也再也猜不到"不知道的人"到底听见了什么。

Jay Conger 在《The Persuasive Leader》里把这件事搬进了会议室。他说专家在说服这件事上，往往是最差的那批人：你越懂一个问题、对某个方案越笃定，就越难站到一个"懂得更少"的人的位置上，去理解他眼里的问题长什么样。这不是性格缺陷，而是一种认知上的陷阱。于是那些最聪明的方案，常常死在了一句"我说得明明很清楚，你们怎么就是不懂"。

我特别在意的是他给的解药方向：有效的说服，不是从"定义方案"开始，而是从"理解对方如何定义问题"开始。最有说服力的人，优先保持好奇而不是笃定，在抛出自己的主张之前，先问足够多的问题。这话听着像老生常谈，但结合"知识的诅咒"，它其实是一道反直觉的功夫——你得主动把自己"知道"的那部分按下去。

这让我想到自己跟人讲一个技术方案的时候。越是对某个实现细节熟悉，越容易一上来就讲细节、讲"最优解"，而对方其实还卡在"为什么要做这件事"的层面。读到这里，我给自己留了一句话：下次想说服谁之前，先别急着证明自己对，先问问对方眼里这件事是什么样。

这段访谈式的书摘叫 [The more you know, the harder it is to change someone's mind](https://bigthink.com/books/the-persuasive-leader/)。以前看这类"说服术"标题总觉得是话术，今天第一次觉得它更像一面照妖镜——照出的是那个"知道得太多、反而说不清"的自己。

### 一句假名言，说出可负担性危机

爱因斯坦没说过那句"复利是世界第八大奇迹"。最早能查到的是 1983 年《纽约时报》的一个专栏，再往前，1916 年加州一份报纸广告里出现过"最伟大的发明"，1925 年克利夫兰一家储贷公司用过"第八大奇迹"。一句被安到爱因斯坦头上的话，其实是一群想卖理财产品的人拼出来的。这是 Ethan Siegel 那篇天文专栏里，最不"天文"的一段。

但有意思的不是这句话是假的，而是它背后的数学是真的，而且正在解释一个我们天天喊疼的问题。复利和线性增长是两回事：一年拿固定 100 块是线性的，17 年后 1700 块；可要是按 4% 复利滚，17 年后是 194 块多，越到后面差距越大。财富的增长叫复利，价格的上涨叫通胀——同一套数学，方向反了过来。

我读到这里才第一次把"可负担性危机"看成一个复利问题。工资很多时候是线性涨的，一年加一点；可房价、学费、医疗费是按比例滚的。当价格在复利、收入在走直线，这两条曲线之间的距离会随着时间越拉越大——这不是谁的错，是数学的错。那些"为什么我们这代人买不起上一代人能买的东西"的困惑，底下压着的就是这么一道指数曲线的形状。

这篇叫 [A fake Einstein quote actually explains the affordability crisis](https://bigthink.com/starts-with-a-bang/fake-einstein-quote-affordability-crisis/)。它讲的是复利、通胀和那句假名言之间的巧合。对我来说，最值得记下的一点反而不是财务上的——是那句假名言提醒了我：很多被我们当真理流传的东西，源头可能只是一个广告。对数字和"名人名言"都保持一点怀疑，也许才是这篇真正想说的。

Vercel Labs 出的"computer use" CLI，让 AI agent 能直接操控你的电脑桌面——点鼠标、敲键盘、看屏幕，而不只是读文本。今天 +2,470，是 trending 榜上涨得最猛的，说明"给 agent 一双能操作界面的手"正在从研究 demo 变成工程工具。

### auto-ontology

NVIDIA 开源的 Python 框架，给数据上面加一层"语义图谱推理"：把结构化数据转成图，让 LLM 和 agent 做确定性的查询生成、更好的上下文检索、更可解释的 AI。今天 +2,050，是榜上另一匹黑马。

### kimi-k3-in-c

一个用 C 写的小东西，把 2.78 万亿参数的 Kimi K3 塞进 8.24 GB 内存、跑在单核 CPU 上。今天 +351 不算猛，但这个工程本身有点吓人——通常这么大的模型要一整块 GPU，这里靠的是极限量化加纯 C 推理。

### floci

"轻、软、永远免费"的 AWS 本地模拟器——在你自己的机器上跑一个能模拟 AWS 服务的环境，用来本地开发测试 Lambda、S3、DynamoDB 这些，不用连真 AWS、不用花钱。今天 +1,090。

LocalStack 是这个品类的老大哥，floci 用 Java 重写、主打免费和轻量。对天天跟 AWS 打交道、又不想在本地测试时烧云账单的开发者，这是 LocalStack 之外一个更轻的选择。边界也直接：它是模拟器，不是真 AWS，行为不可能 100% 一致，上线前还是得在真环境里过一遍。
