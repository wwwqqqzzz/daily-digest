### 六百种接不上的水带

1904 年 2 月 7 日，巴尔的摩起火。周边城市的消防队连夜赶来，到了火场却发现一件荒诞的事：他们的水带拧不上巴尔的摩的消防栓。螺纹不一样。于是几千人带着装备站在旁边，看着火烧了三十多个小时，一千五百栋建筑被毁。

这不是运气差。当时全美国的水带接口和消防栓口径有大约六百种变体。美国国家标准局的 Albert Merrill 事后做过统计，这个数字就是他数出来的。更微妙的是它为什么存在：口径和螺纹各不相同，恰好能把客户锁在自己的供应商那里，兼容性差是一种商业模式。

后来的事很直白。1905 年，美国国家消防协会成立专门委员会，规定螺纹的直径和每英寸牙数，这就是今天北美仍在用的国家标准螺纹。同年，国家标准局自己办公楼南北两栋之间也着了一次小火，员工发现两栋楼的水带同样接不上——同一套毛病在自己家里重演了一遍。

真正让人不舒服的是时间尺度。一百年后，NIST 回头去查美国人口最多的 48 个城市，只有 18 个真的换上了国家标准消防栓。标准发布了一百年，惯性还在赢。

> [!tip] 简介
> 监控系统只报你让它盯的东西；bug 往往出现在你没让它盯的那部分。

这句话本身就是一个产品的全部理由：你已经有 Datadog、Sentry、Grafana，你还是从客户嘴里第一次听到 bug。因为告警是被人预先定义的，而"没被预想到的错误"天然不在告警清单里。

superlog 的位置很明确——它不替换你的监控，而是叠在上面：扫每一条日志，找没人设过告警的新错误模式，自己查根因，跳过你已经在盯的部分，然后给出修法。你用自己的 coding agent 改，或者让它开 PR。创始人 Nicolò 和 Arseniy（前 Datadog）给的数字是 100 多家创业公司在用，87% 的建议修复被合并。

值得注意的是这个品类正在快速成形。过去一年最热的一批工程工具都在做同一件事：把"值班工程师半夜看日志"翻译成"agent 半夜看日志并提出补丁"。它和 PagerDuty 那一代的分工不是替代，是分层——告警层继续报已知问题，推断层处理未知问题。

值得警惕的部分在于 87% 这个数字的语境。合并率高不代表发现率高：一个只提"容易修的问题"的系统可以轻松保持高合并率，真正难的是那些没有明显堆栈、只在特定数据下出现的错误。另外它的价值随接入深度上升，接一个服务看到的是样本，接全了才是能力，这意味评估成本不低。首发评论里有个问题问得很到位：当它建议你补日志或加指标时，这个建议是不是也以 PR 的形式来——这其实在问，它是工具，还是同事。

> [!info] 简介
> 把设计稿背后的判断变成 agent 每次都要遵守的规则，而不是每输出一次修一次。

创始人 Grant 做了九年数字产品公司，他的观察是：客户付费买的从来不是那些界面，是界面背后的判断。然后 AI 让执行变免费了——任何人几分钟能生成一个落地页，而做设计的人不在那个循环里，于是他们陷进同一个动作：追着每次输出修同一类错误。

他自己给这个现象下了一句很锋利的话：让东西变垃圾的不是 AI，是缺失的方向。所以产品的形态不是"再给你一个生成器"，而是把已有的设计反向变成指导——指向你现有的稿子，它把你的决定写成 agent 在所有 AI 工具里都要遵守的规则；输出偏了，你改一次系统，下一次输出就对了。

这个定位对准的是今年设计与工程之间最真实的裂缝。设计系统这类东西原来的消费者是人，现在多了一个消费者是模型；而模型不读你的品牌手册，它读的是提示词和环境里的约束。谁能把这层约束变成可执行的文本，谁就掌握了实际的一致性。

没解决的问题同样明显。评论区里一个独立开发者问得很具体：他做 SwiftUI 应用，agent 几分钟能搭一个页面，但看不见他脑子里的品味，于是间距和层级一再漂移。他关心的是——只看现有 App 的截图就能用，还是必须先有 Figma 文件或设计系统？这道题几乎决定了产品可用的起点。另一个问题是模糊规则怎么办，比如语气这种东西，能不能变成 agent 真能拿去考试的标准。首发只有五条评论，说明它还在很早期；而"把品味写成规则"这件事的难点，恰恰在于最难写下来的那部分才最值钱。

> [!quote] 简介
> agent 写出来的东西发成一个链接，团队在具体位置上留言，agent 读完再发新版本。

整条链条是从一个很小的尴尬开始的。创始人 Nabeel 的 agent 写了一份系统设计文档，他想让团队在文档上直接评论——粘到聊天里格式全丢，截图丢了上下文，反馈散在聊天和邮件里，最后没人能把意见交回给 agent。

Glass Page 的处理方式是给"agent 的产出"一个正经的落点：Claude、ChatGPT、Cursor、Codex 或任何接了 MCP 的 agent 都能把自己做的东西发布成一个带链接的 Pane；多个 Page 摊在一张 Canvas 上，可以平移缩放看流程或一组界面；团队在确切的位置开评论线程；agent 读回这些评论，改完发一个新版本，而那个 Latest Link 永远指向当前版本，谁都不会再评审一份过期的东西。

它和老一批协作工具的区别在于谁是第一读者。Notion、Google Docs 的评论流是为人设计的，模型的读法只能靠喂文本；Vercel 的预览链接解决的是"跑起来看"，不解决"读起来评"。这里把"agent 能读回评论"当成了核心接口，等于假设未来的审稿循环里有一半参与者在机器那一侧。

天花板的判断也直接：免费额度十个 Pane，对一个真在用的团队偏紧；价值的成立依赖 agent 端配合——如果你的 agent 不会回来读评论，它就只是一个好看的分享页；权限、留痕、谁能看到哪个版本这些企业最在意的细节，在一个个人项目里通常还没答完。十二条评论里最值得看的是关于"如果 agent 改错了，历史版本怎么追溯"的追问，这其实是所有 agent 协作工具都要过的同一道门。

> [!note] 简介
> Rust 写的开源参数化 CAD，把"建完模型直接躺平送去打印"这一段接上了。

参数化建模这件事的定价一直很别扭：够用来做真零件的工具通常贵、重、绑系统或绑云，免费的那些在最后一步掉链子——模型建好了，怎么变成能打印的东西还得另找工具。Three Bugs Studio 想做的就是这一个薄薄的空缺：一个轻量应用，Windows、macOS、Linux 都能跑，从建模管到切片前一步。

v1.1 的能力列表已经不像早期原型：带约束和尺寸的草图，拉伸、旋转、扫掠、放样、倒角、抽壳、孔、螺纹，每个尺寸都能回头改，变量和方程可以驱动它们；STEP、STL、3MF、OBJ、DXF 都能直接打开，从 SolidWorks、Fusion 360、Onshape 导出的 STEP 进来时单位和形状是对的；能查悬垂和薄壁，把零件平放到打印床上，导出 3MF 给切片器；多零件可以用配合装成装配体，再出带剖视和标注的二维工程图，导出 PDF、SVG 或 DXF。

和 FreeCAD 比，它至少把"开箱能不能直接干这件事"当成设计目标，而不是当成一个插件生态问题；和 Onshape、Fusion 比，它是本地的、免费的、代码开着的，代价是你要接受一个还在一版的软件。用 Rust 写 CAD 内核这个选择在今天是合理的：几何计算密集、要求确定性、还要跨三个平台，这类活不适合脚本语言。

该说清的风险：v1.1 意味着装配和工程图这两块——恰恰是商用 CAD 里最难、最靠时间打磨的部分——还很浅；开源 CAD 的历史教训是内核好写、约束求解器和兼容性难维护；而"能打开 STEP"和"能正确处理任意 STEP"之间，中间隔着几百种边界情况。四条评论不算热闹，但这类项目本来也不是靠一天的热度活下来的。

## 🧠 Big Think

### 大脑的两半，两种做法

Iain McGilchrist 一开口就在拆一个我从小就信的版本：八十年代、九十年代那套说法——左脑理性、可靠、无趣，右脑浪漫、有创意、靠不住。他说这里面每一项都是错的。差别确实存在，解剖上、生理上、神经心理上都能测出来，但差别不在"做什么"，而在"怎么做"。

他说的"怎么做"不是指机制，是指接近一件事的姿态。这句话让我停了一下。因为一旦把差别挪到姿态上，左右半球就不再是两个部门，而是两种看同一件东西的方式：一种把东西拆开、命名、装进盒子；另一种留在关系和上下文里，看它此刻是什么。他自己后来提到，我们太容易滑进左边那一半——我可以把它拆开给你看，但这只给你一堆被从上下文里取出来的碎片，你已经不知道它们原本是什么了。

他走到这条路上是偶然的。在牛津读神学与哲学时，他去听关于心身问题的研讨会，觉得一件奇怪的事在反复发生：人们讨论文学作品的时候，话突然变得极度抽象、抽离了身体。后来某个下午他差点没去，去听了 John Cutting 关于右脑的讲座——那是他第一次听到有人认真讲右半球到底做什么。他自己说，那天下午他的人生方向变了。

访谈后半段转去讲"什么样的人生算是兴旺"，这部分反而最扎实。他说心理学文献里被反复验证的只有三样：属于一个小共同体，那种你信任、共享价值、一起吃饭、彼此照看孩子的尺度；亲近自然，他给的门槛低得可爱——每周三次、每次二十分钟，关掉手机，安静地待在一个公园里；以及觉得自己属于一个更大的、可以称之为神圣的秩序，信教或不信教都行，打坐、祈祷、什么都不做只是知道自己在一个更大的上下文里，也算。

然后他讲 Viktor Frankl，讲那本《Yes to Life in Spite of Everything》，讲苦难不会是你主动去求的东西，但它的存在会改变你能成为谁，还会给你一样东西：你可以接收、共振，再把它传出去。他说他注意到做疗愈的人常常有一段自己的苦。这一段我没有被说服，但也没有反感——它更像一种从长期看人得出的印象，而不是一个可检验的结论。

我把这段访谈当成今天的镜子，是因为我最近干的活几乎全是左半球的手艺：把一件含糊的事拆成七个步骤，给每一步定字段，把判断变成可执行的规则。这有用，也确实有人愿意为此付钱。但拆完之后，最难说清的那部分往往消失了，而消失的恰好是价值所在。这篇收在 The Well 的[这个系列](https://bigthink.com/the-well/how-to-navigate-the-world-with-two-halves-of-one-brain/)里，他还讲了一句我很喜欢的话：犹太智慧文学里有一条，你不被要求找到这个问题的答案，但你不被允许放弃尝试。想清楚这一点，交付之前那句"这样就行了吧"会说得轻一点。

给自己留一句：下次写完一份看起来很完整的方案，先别发，对着它问一遍——这里头有没有一个东西，是我拆开之后就没了。

### 从亚原子到宇宙，最空的是星星之间

有一个问题简单到我从来没想过：拿一个东西的大小，去比它到下一个同类东西的距离，哪个尺度上的比值最夸张。Ethan Siegel 把这件事故意从量子做到宇宙，八个尺度排下来，答案不是最大的那个，也不是最小的那个，是中间那一层。

恒星之间的空，大得没有道理。太阳直径一百四十万公里，到比邻星四点二四光年，四千万比一；球状星团核心那种挤到极限的地方，恒星间距零点一五光年，也还有百万比一；到了超弥散星系，恒星间距能拉到二十光年，比值超过一亿比一。他给的那个换算我记了很久：如果太阳是一个篮球，下一颗恒星会在地球的另一边，不在同一座体育馆里，甚至不在同一个城市。

第二名反而在最小的尺度上。原子核直径约十的负十五次方米，电子在十的负十次方米外，十万比一。他把原子核缩成放在 Pepperdine 大学的一个篮球，电子就在二十四公里外的圣莫尼卡码头上。这一层空得让人不舒服——我们身体里绝大部分是空的，这句话听过很多次，但换成"码头到校园"的距离才真的有体感。

后面的排名开始反直觉。行星之间三千到两万八千比一，第三；人类之间反而排第四，连格陵兰那些定居点之间三到七公里的稀疏，也只有几千比一；银河系和仙女座之间只有二十五比一——银河系是篮球在篮筐下，仙女座在罚球线；星系团之间四到七比一，把邻居凑一凑，能在半场打一场球。也就是说，"空"并不随尺度单调增长，它不是宇宙的一个统一属性，而是每一层各自的历史留下的一个数字。

我在这篇里最在意的是一个更小的事实：如果把八十三亿人均匀摊在地球表面，人和人之间平均隔两百七十米；东京丰岛区最密的两个邻居只隔三点二五米；东京早高峰的地铁车厢里是四十厘米。同一句话——"人类分布不均"——换成这三个数字，重量完全不一样。数字的说服力经常不来自它多精确，而来自它有没有找到一个能站人的位置。

这件事对我有用，是因为我做的活基本都在"层"上：数据一层、接口一层、调度一层、人一层。默认的直觉是越往上越稀、越难、越抽象。这个排名提醒我，最空的那一层可能在中间，而最挤的那一层可能看起来最宏大。以后想说"这个领域很散"的时候，先别凭印象，先量一下它的距离比。

原文在 [Starts With A Bang](https://bigthink.com/starts-with-a-bang/size-distance-comparison-subatomic-cosmic/) 这个专栏里，他把每一层都配了同一套换算，读起来像给宇宙做了一次体检。
