### 澳大利亚真的对鸸鹋宣过战

1932 年，澳大利亚政府派了一支军队，带着机关枪，去打一群鸟。结果鸟赢了。

那一年西澳大利亚闹旱灾，两万多只不会飞的鸸鹋从内陆迁徙到小麦产区，踩踏庄稼、撞坏围栏。种地的多是参加过一战的老兵，他们向政府请愿，政府还真派了皇家炮兵的梅雷迪斯少校带了两挺刘易斯轻机枪去"作战"。

问题是鸸鹋太难打了。它们跑起来时速能到 50 公里，还习惯一受惊就四下散开，根本不给机枪"扫射"的机会。整场行动打掉了近万发子弹，打死的鸸鹋不过几百只，平均十发子弹才换一只鸟。没多久军队就灰溜溜撤了，媒体戏称这是"鸸鹋战争"，还笑话说这场仗鸸鹋赢了。

有意思的是，后来真正管用的是一套赏金制度——悬赏让农民自己去打。政府这才明白：对付几万只跑得飞快的鸟，正规军不如利益驱动。

### AXL

> [!abstract] 简介
> 面向 AI 产品创始人的 GTM 副驾驶，通过 MCP 协议把 1200 多项操作交给 ChatGPT、Claude 或 Cursor。

### Sage2

> [!tip] 简介
> 把实时对话变成结构化数据和即时动作，给开发者用的 API。

Levanto Labs 的 Sage2 做的是对话理解里最脏的那部分活：从自然语言里把日期、金额、时长这类值抽出来，追踪用户意图的变化，并随着对话推进做流式决策。它最让我在意的一个设计是"source-linked results"——每个抽出来的值都能追溯到原文里对应的话，而不是给你一个来路不明的自信数字。单个流式会话里最多同时跟 32 个问题，reasoning、网页 grounding、视觉能力都在 beta。

这类工具的位置，夹在"直接调大模型"和"用现成的客服平台"之间。直接调模型，你要自己写 prompt、自己做校验；用客服平台，又绑死了别人的流程。Sage2 只卖中间那一层：抽取和决策，动作还是留给你的应用去执行。

边界在于它是个开发者工具，不是开箱即用的产品——你得会写代码接它。评论区里有人问得很实在：用户在一段对话里改两次需求，抽出来的值会带新 source 一起更新吗？这正好是这类中间件最容易翻车的地方。

### Inkling 2 Small

> [!example] 简介

### outages.live

> [!info] 简介
> 给 coding agent 的免费故障源，把各家官方 status page 聚成一个 feed。

Polylane 团队做的一个小 side project，解决的痛点非常具体：你的 agent 开始怪你的代码，其实可能是 Stripe 或 OpenAI 自己挂了。outages.live 把云、AI、支付、开发者工具的官方状态页聚合成一个 feed，每几分钟刷新一次，然后通过 MCP server 塞给 Claude Code、Codex、Cursor、OpenCode、Copilot，让 agent 在动手"修 bug"之前先查一眼"是不是服务商挂了"。

免费、无登录、无 API key，也支持 RSS、Atom、JSON Feed、Slack 订阅。这种"零摩擦"是它最大的卖点——你不需要为它配任何东西，就能让 agent 多一层判断。

它的边界很清楚：只是聚合官方状态页，而官方状态页往往"承认故障"很慢——恰恰是 agent 最需要它的那几分钟它可能还没报。评论区有人就点破了这个时间差。所以它是锦上添花的护栏，不是真正的监控替代品。

### Agent Clan

### 第一次 DNA 鉴定，洗清了一个认罪的人

1986 年，英国莱斯特郡一个叫 Narborough 的小村庄，警察把一名 17 岁的厨房帮工理查德·巴克兰当成了连环案凶手。他在审讯里承认杀了 Dawn，警方也几乎认定他还和两年前的 Lynda 案有关——只差一份能把两起案子一起钉死的证据。

于是他们找到了遗传学家 Alec Jeffreys，请他用刚刚成熟的 DNA"指纹"技术做个比对。这是这项技术第一次被用在刑事案里。结果出来了，却完全不是警方想要的：巴克兰的 DNA 和 Lynda 案现场的对不上。他不光没杀 Dawn，也没杀 Lynda——一个已经认罪的人，就这样被 DNA 洗清了。他成了历史上第一个靠 DNA 被证明无辜的人。

我特别在意的是这件事的顺序。我们本能地以为，一项"破案新技术"第一次出场，应该是帮警察抓人的。可它第一次真正在法庭上说话，说的是"你们抓错了"。它推翻的不是罪犯的狡辩，而是一个活人亲口说出的供词。一个会"说不"的工具，比一个只会"说是"的工具，价值大得多。

后来的事大家都知道：DNA 反过来抓到了真凶 Colin Pitchfork，也成了翻案的利器。美国 Innocence Project 用 DNA 洗清了 203 个冤案，其中还有死囚。这项技术的故事，取自遗传学家 Turi King 的新书，[Big Think 节选了其中最戏剧性的一段](https://bigthink.com/books/dna-profiling/)。

这让我想到自己每天在和 AI 打交道时的一个习惯：我总希望它给出一个确定的答案，越快越好。但真正值得信任的判断，往往是那个愿意停下来、告诉我"这里可能不对"的信号。第一次 DNA 鉴定的历史，像个提醒——最珍贵的不是"确认"，是"证伪"。

### 天文学家怎么知道星星有多远

小时候去天文馆，屏幕上总是一行干脆的答案：某颗星距离地球多少光年。我从来没想过一个更傻的问题——我们又没法拿尺子量，这些数字到底是怎么来的？

答案是一架三级跳的梯子。第一级叫视差：地球绕太阳转，近处的星星在天幕上会轻微地来回挪一下，就像你左右眼轮流看眼前的手指。量出这个挪动的角度，用地球轨道的直径当基线，三角函数一算，距离就出来了。这是最直接的方法，但只够得着几千光年以内的星星，盖亚卫星把它推到了前所未有的精度。

第二级叫"标准烛光"：找到一些亮度天生固定的天体。造父变星会规律地脉动，而且脉动周期和它的真实亮度有固定关系——这是 Henrietta Leavitt 在 1910 年代发现的。测出周期，就知道它本来该有多亮，再和看到的亮度一比，距离就出来了。哈勃当年就是靠它算出仙女座星系的距离，第一次证明那是一个独立的星系，而不只是银河系里的一团雾。

第三级是红移：宇宙在膨胀，越远的天体退得越快，光就被拉得越红。哈勃定律把"退行速度"和"距离"挂上了钩，所以只要测出红移，就能一路推到几十亿光年之外。

让我记到现在的，是这套梯子的地基：它每一级都建立在一个"相信宇宙某些规律是稳定的"的假设上。从脚下的地球轨道，到远处恒星的脉动，再到整个宇宙的膨胀。我们没有直接量过任何一颗星的距离，却敢把这些数字精确到小数点后好几位。Ethan Siegel 的专栏[把这三种方法的来龙去脉](https://bigthink.com/starts-with-a-bang/how-far-away-stars/)讲得很细，比我这里清楚得多。

### agent-browser

Vercel 出的浏览器自动化 CLI，给 AI agent 用的。它不是给你人用的浏览器，而是让 agent 能像人一样打开网页、点击、填表、截图的命令行工具。今天 +815 星，说明"让 agent 自己上网操作"这个需求正在爆发——越来越多人在给 agent 配一双真正能干活的手，而不是只让它生成文字。
