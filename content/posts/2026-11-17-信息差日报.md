### 罗马混凝土会自己长回去

罗马人两千年前浇筑的港口和海堤，泡在海水里不但没散架，反而越来越结实。现代混凝土的设计寿命通常按 50 到 100 年算，而罗马的那些结构到现在还在用，这件事长期被当成"古人配方失传"的浪漫故事。

2023 年 MIT 的 Admir Masic 团队给出了一个相当朴素的解释：关键不是神秘配方，而是罗马人偷懒的方式。他们不用事先消解好的石灰膏，而是把生石灰直接和火山灰、水一起拌——这个过程叫热混合（hot mixing），反应放热，混合物里留下一块块脆的石灰碎块。裂缝出现时，会优先穿过这些碎块，水一渗进来，碎块里的石灰就溶解、重新结晶成碳酸钙，把裂缝自己封上。团队按古法做试块、人工敲裂，三十天内裂口就愈合了。

有意思的是，这个"缺陷"其实是关键。现代混凝土追求均匀、干净、无杂质，于是裂缝只能一路贯穿，没有可以牺牲的碎块来换一次自愈。罗马人留下的一堆不均匀，反倒成了它的免疫系统。

> [!example] 简介
> 给 AI 员工用的操作系统：定角色、教业务、共享上下文，再用 1400 多个模型和 1500 多个已有工具把它们接进你的公司。

"AI 员工"这个词被用滥了，但 Boost.space 这一版至少把最难的部分说清楚了：不是模型不够强，是几个 agent 之间不共享记忆。

它的设计前提是让一群专职 agent 各自扮演角色——查竞争对手的、改商品目录的、处理客服的——然后共享同一份上下文、技能和工具。厂商给的数字是 1400 多个 AI 模型、1500 多个已集成的工具。说白了，它卖的不是智能，是"公司内部的公共记忆"和权限层。

创始团队的路径也值得看一眼：他们先做了几年 Boost.space 的数据统一与安全（今年进了 Capterra 数据管理类前五），再把这层数据底座往上抬成 agent OS。这个顺序合理——agent 要干活，先得有干净的数据和明确的访问边界。

边界同样明显。这是给有 IT 预算的公司准备的东西：接入、角色配置、权限设计都要人做，个人用户拿它当玩具会很痛苦。竞品也挤：往上是 OpenAI、Anthropic 自家的 agent 平台，往下是 n8n、Zapier 那种工作流工具正在往上长。它的差异点是"多 agent 共享上下文"这个具体切口，而不是又一个 agent 编排界面。

> 从"预约时间"扩成"见面这件事"：卖票的活动、找本地服务、浏览器里的永久会议室，一起上。

Cal.com 这次不是在原来的产品上打补丁，是把自己重新定义了一遍。CEO Peer Richelsen 在首发里写得很直白：光靠排会议的 SaaS，到 2031 年做不成十亿人的生意。

于是 v7 一次放了四样东西。cal.com/events 干的是活动票务，从公园野餐到音乐节，能卖 VIP 票、发 Apple Wallet 通行证、让嘉宾名单里的人互相约时间；cal.com/discover 是本地服务发现，输入"我牙疼"就给你找附近的牙医，还能接 openclaw、grok bot 这类 agent，学会"帮我约牙医"这种说法，要是商家不在平台上，它就用 AI 去打那个公开电话；cal.video 是浏览器里的永久会议室，不用装 app、访客不用注册，还带转录和录制；cal.com/desktop 管会议、记 AI 笔记，含在订阅里。

这个方向判断得对：AI 把"排时间"这件事本身的价值压得很低，剩下的价值在"人真的见了面"。但风险也在这里——这四条线，每一条对面都站着一个巨头：票务是 Eventbrite 和 Luma，本地发现是 Google Maps，会议室是 Zoom 和 Meet。

### ChatGPT Wallet

<div class="carousel">
  <img src="https://ph-files.imgix.net/ae541568-809e-4e86-8ad1-c36e2f980ef2.jpeg?auto=format">
  <img src="https://ph-files.imgix.net/04f8afdd-8a58-46fb-a591-1b8bf17a613d.png?auto=format">
</div>

> [!info] 简介
> 让 ChatGPT 的 agent 替你把账付了，但 agent 和商家都看不到你的卡号。

这件事的技术方案比宣传语更值得看：卡组织给 agent 发一个支付 token，agent 拿着 token 去下单，商家拿到的是 token 而不是卡号，agent 自己也从没见过卡号。付款前你审物品、总额和用的哪张卡，然后用 Face ID 或指纹确认。合作方是 Amex、Mastercard、Visa 三家。

它解决的是 AI 代理消费里最尴尬的一环——你要么把卡给 agent（等于把额度全开），要么每笔都自己动手（那 agent 就没意义）。token 化的思路是把"授权"从一次性变成有范围、可追溯的东西，思路本身没问题。

真正的问题在评论区那一句：酒店在退房时要收一笔原订单之外的押金或杂费，一个只对"这次预订"有效的 token 会怎么处理？这不是刁难，这是 agent 支付的死穴——现实世界的账单会漂移，而 token 是按预期锁定的。谁先把这个"授权范围 vs 实际支出"的落差设计明白，谁才算真的做成。

另外有人开玩笑问，能不能让 agent 顺便劝自己别买不需要的东西。这玩笑其实挺准：现在整套设计都在优化"买得更顺"，没有一个环节在优化"别买"。

### Trusty CSV

<div class="carousel">
  <img src="https://ph-files.imgix.net/1a78b88b-74b5-4d0c-8d7e-027a9de1dacc.png?auto=format">
  <img src="https://ph-files.imgix.net/6ad453d3-770d-4702-8404-4513c47ad5d9.png?auto=format">
  <img src="https://ph-files.imgix.net/7d3cb491-22a8-4024-921d-c52ae0932612.png?auto=format">
</div>

> [!note] 简介
> 像改代码那样改 CSV：只有你动过的单元格才会变，保存后能看到 diff。

做 Calmly Writer 的 Yusef Hassan Montero 又做了一个小而准的工具。他描述自己的痛点很具体：Excel 会在他没要求的情况下改东西，文本编辑器给他一墙逗号，而正经的数据准备工具要求他先把文件导进一个项目，才能改一个错字。

Trusty CSV 就是把 CSV 当文件打开、把列对齐、让你直接改：聚类相似值、筛选、join、透视，也可以就在单元格里敲。每一步一个 Ctrl+Z，保存后 diff 只显示你改的地方。免费、跑在浏览器里、文件不出本机，桌面版在路上。

真正的卖点其实是那个 diff。CSV 一旦进了版本库，Excel 一次"贴心"的重新格式化就能让 diff 变成一片红，review 的人根本看不出你改了什么。把 CSV 编辑收敛成"只改我碰过的单元格"，是把数据文件纳入工程流程的必要条件。

边界也清楚：它面向的是几十行到几千行的修补和对账，不是拿来做分析和聚合的。真要对百万行做统计，还是得回 SQL 或脚本。有人问大文件的 diff 撑不撑得住，创始人没在评论区答——这大概就是它当前的天花板。

> 描述一款字体，或者拍一张自己手写的页面，得到一个能装进系统的字体家族。

Rishi 的出发点很实在：定制字体要几周时间和一个字体设计师，大多数品牌最后都用了同一批免费字体；而图像 AI 只会"画"出字母的样子，你没法拿它打字。

Punchcutter 的做法是把它塞进你已经在用的 AI 里：在 Claude 里敲 /punchcutter，或者在 ChatGPT、Codex、Cursor 里当 MCP server 用。然后选一条路——用一句话描述（"一款安静的新怪诞体，五个字重，叫 Burin"）、打印字格纸手写后拍照、随手拍一页现成的字、给一张喜欢的图定调、或者从开源字体改。产出是 TTF、OTF、可变字体和 webfont，做过间距和字距，过 155 条质检规则，另配一个 Studio 应用做设计实验室和样机。

开源、MIT 许可、免费，这是它最容易被低估的部分——字体工具长期是这几家厂商的封闭生态。

但评论里那条反对意见值得留在这儿：作为概念很酷，可示例里的结果还没到字厂的水准；手写字体允许不完美，可如果是要给品牌或网站用的字体，"描述一种感觉"产出的东西必须敢和真字体设计师比。这个批评成立，也正好划出边界：它现在适合快速试风格、做个人字体、给原型配一套临时字体，不适合拿去交给客户当品牌资产。

## 🧠 Big Think

### 我们给自己家称了一次重

天文学家终于把银河系的质量称出来了：1.19 万亿个太阳质量。这个数字听上去只是在填空，但它背后是一件别扭了近一个世纪的事——我们住在这个星系里面，却一直没法给它称重。

难的地方很具体。星系的质量有八成半是我们看不见的东西，只能靠运动去反推：看得见的星光是重子物质，约占一成半，剩下那部分暗物质不发光，只能从星星怎么跑动里读出来。可要读运动，先得知道星星有多远、往哪个方向跑，而我们在盘面内部，视角被自己的星系挡着。所以过去十年的估值区间一直跨度惊人——从五千亿到近两万亿太阳质量，差四倍。我在意的是这个"差四倍"：不是学者不严谨，是测量对象天生不配合。

这次的解法有点像找一群住在郊区的人来给整座城市测重。DESI 的巡天本来是为了看极远的宇宙，却顺带把银河系晕里一万多颗星的光谱拍了下来；这些星离银心三万三千到三十一万光年，正是那种"住在荒郊、但被整个城市的重力牵着跑"的样本。再配上 Gaia 给出的横向自行，就有了三维的位置和速度。接着他们把这批星的运动跟 24 个已知质量的人造星系模拟结果去比——先在知道答案的模拟里试出每种算法的偏差，再拿校准过的算法去测真的。

结论干脆：在 26 万光年范围内，包住的质量是六千三百六十亿太阳质量，误差只有百分之六到七；外推到整个晕，是 1.19 万亿太阳质量，误差一到两成。之前那个"银河系偏轻、暗物质很少"的假说，基本被这批远郊的星否掉了。

我惦记的是方法本身。它没有造新望远镜，也没有推翻什么理论，只是换了一批观察对象——从挤在市中心、被各种效应搅乱的星，换成外面那些轨迹干净、又确实被整体引力约束住的星。很多时候我们以为自己缺的是更精密的仪器，其实缺的是一个更好的取样位置。这篇来自 Ethan Siegel 的专栏（[Starts With A Bang](https://bigthink.com/starts-with-a-bang/astronomers-weigh-milky-way/)），他之前写过一篇[关于"没有暗物质的星系"的文章](https://bigthink.com/starts-with-a-bang/dark-matter-free-galaxies/)，两篇摆在一起看更有意思：一边是暗物质多到撑起整个晕，一边是几乎完全没有它的星系，宇宙在这件事上并不整齐。

给自己留一句：下次看到"某某的总量是多少"这种数字，先问误差多大、取样的是谁。差四倍和差百分之七，说的其实是两件完全不同的事。
