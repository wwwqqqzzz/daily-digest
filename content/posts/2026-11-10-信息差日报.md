## 🧊 冷知识

### Deadline 是一道死亡线

现在人人都在赶 deadline，但这个词的字面意思其实是"死亡线"——它诞生在美国内战的战俘营里。

1864 年前后，南方邦联在佐治亚州安德森维尔（Andersonville）等战俘营里，会在围墙内几米处划出一道界线。任何跨过这条线的战俘，看守会当场射杀。这条线就叫 dead line，一道"越过去就会死"的线。

战争结束后这个词没消失，而是搬进了印刷厂。报纸的排字机上有条物理界线，超过那条线的文字就排不进版面，记者必须在"deadline"前交稿。从此"死线"从"越过会死"变成了"越过会误事"。

有意思的是，一道 160 年前会要命的线，最后成了现代人最日常的焦虑来源。你今天赶的每个 deadline，字面上都是在赶一条曾经真的会死人的界线。语言很少这样完整地保留一段暴力史——它只是把"死亡"藏进了一个谁都不再害怕的词里。

### Terse - Durable Actors

> [!abstract] 简介
> 开源版的 Cloudflare Durable Objects，给多人 AI 产品做有状态基础设施。

Terse 的核心原语是一个叫 "Durable Actor" 的东西：一个一次只处理一个请求、自带 SQLite 数据库的小服务器，全局只有一个实例、按名字寻址。每个 agent 可以拥有自己的 Actor，每个用户通过 websocket 连到那个 Actor，天然横向扩展。典型场景是聊天系统（ChatGPT、Codex 那类）、协作工具（Notion 那类）、agent 集群（Devin 那类）——总之就是"多人、实时、有状态"的 AI 应用。

它的位置很明确：Durable Objects 是个好原语，但被绑死在 Cloudflare 上。Terse 做的是把这个原语带走——开源、MIT 协议、带 helm chart 可自托管，主打"不锁定、无内存上限、内建可观测性"。这是 YC Fall 2026 的项目。官方给的数据是有状态读 p50 1.51ms、p95 2.28ms，写得有板有眼。

边界也清楚：评论区有人点破，Durable Actor 管的是"有状态"而不是"有状态执行"——它不像 Temporal 或 Azure Durable Functions 那样管执行编排。而且还没公开客户和融资额，冷启动下的真实表现待观察。适合已经在写多人/实时 agent 应用、又不想锁进 Cloudflare 的团队。

### ProtoMap

> [!tip] 简介
> 给 AI coding agent 的 gRPC/Protobuf 上下文引擎，一个不烧 token 的确定性服务图谱。

HoundDog.ai 做的 ProtoMap，本质上是一个用 Rust 写的静态扫描器：把整个组织代码里每一个 gRPC 服务、每一个 message、每一个字段的关系，映射成一张"服务图谱"，每次 commit 自动更新。工程师可以用自然语言问这张图，coding agent 通过 MCP 拿到同一张图。

它解决的痛点很实在：AI coding agent 要理解代码依赖，只能反复读代码、烧 token，而且大公司代码库根本不可能全 checkout 到本机。ProtoMap 的做法是"确定性图谱 + 零 AI token"。官方基准：8X（官网另写 13×）token 减少、7.7× 更快出答案，针对一个数百万行的 monorepo 场景。

边界在于它管的是 gRPC/Protobuf 生态——如果你不用 proto，价值就大打折扣；而且它解决的是"理解代码"这一层，不是 agent 的推理能力本身。免费开源、单机免费，企业版云或本地部署，支持 Go/Java/Kotlin/C#/Python/TS/JS/Rust/Swift。

### Egoist AI Passport

> [!example] 简介
> 一个"AI 时代的密码管理器"，把个人上下文随身携带，按授权给不同 AI app 用。

Y Combinator S26 项目，$3M 种子轮（YC、Goodwater Capital，以及 DeepMind/Meta 的科学家参与）。AI Passport 是一个用户自有的"上下文层"：把偏好、目标、历史、健康、旅行等信息集中在一处，通过 "Sign in with AI Passport" 的 OAuth 给各家 AI app 按需授权——限定用途和时长，可随时撤销，还能看到每笔授权的审计记录。

创始人的观察很直接：现在 ChatGPT 知道你的一些事，Claude 知道另一些，邮箱、日历、Slack、GitHub、Spotify 各有一份关于你的碎片，而你自己没有控制权。AI Passport 想做的是 "Link 对支付信息做的事"，只不过对象是个人上下文。对用户永久免费。

这是个典型的双向冷启动难题：只有足够多 app 接入、足够多人持有 Passport，上下文层才有价值。而且"把所有个人数据集中一处"本身就是信任门槛——它把风险集中了。适合关注数据主权、又确实频繁在多个 AI 助手之间切换的人。

### Arcjet AI security models

> [!info] 简介
> 给 AI agent 的运行时安全平台，上线一组专为 agent 行为分析训练的安全模型。

Arcjet 是给 AI agent 做运行时安全的平台（检测 prompt injection、授权 tool call、脱敏、挡滥用）。这次上线的是三个专有安全模型：Himalia 1（通用 prompt injection 检测，已 GA）、Thebe 1（针对 coding agent，区分正常开发活动 vs 藏在工具输出、网页、仓库里的恶意指令）、Carme 1（针对自主安全 agent，识别试图诱导泄露密钥、弱化安全控制、引入恶意依赖的指令）。

创始人 David Mytton 那句"通用模型检测不了 prompt injection"点破了行业现状——通用大模型对针对性注入攻击误报漏报都高。Arcjet 的差异化是"专门训练 + 会话级分析"：把可疑内容对照 agent 的任务、工具活动、会话历史来判断，能抓跨多轮交互的渐进式攻击。

边界：它是"in-code / agent hook 内"的执行路径防护（通过 Claude Code、Cursor、Copilot、Codex、Muse Code 的 hooks，不用改代码），不是网络层网关，和 Zenity 这类面向 SaaS agent 治理的平台是互补而非替代。Thebe、Carme 还只是 early access，实战效果待检验。

### GitHub New PR Overview

> [!tip] 简介
> GitHub 官方把"PR 能不能合"的答案提到最上面，公共预览。

这是 GitHub 官方下场做的一次产品发布（公共预览）。新 Overview 页把 merge 状态和下一步可执行的动作，压缩成一个"就绪摘要"放到 PR 顶部。GitHub 的 David Poll 在帖子里点破痛点：agent 时代 PR 时间线越来越吵——agent 推 commit、自己留 review 评论，全落进时间线，真正需要的信息反而难找。团队重新思考的起点就一句话："你现在最需要知道什么？"

### If You Read This

> [!info] 简介
> 一个像"死人开关"一样工作的每日打卡 app——你不打卡，它就通知你信任的人。

这个概念叫 dead man's switch（死人开关/防呆开关）：机器通过"检测不到正常信号"来判断异常。最早用在火车和重型机械上——司机必须持续按住一个手柄，一旦松手（睡着了、心脏病发、失能），列车自动刹车。"If You Read This" 把这个原理搬到了手机上：每天定时打卡，错过就自动通知你预设的紧急联系人。

这个品类一直在（Snug、DeadSender 等），但今年这波"独自居住的年轻人 + 远程工作 + 独居老人"让需求变真实了。它归在 Health & Fitness / Messaging 分类下，说明团队把它当成"健康与安全"而非"效率工具"。免费、Android 优先。

边界：这类 app 的价值全压在"可靠性"上——如果通知没发出去，它就是零。而且它解决的是低频、极端场景，日常存在感很低，容易装了就忘。适合独居、独自旅行、有慢性病或高危工作的人。它更多是一份"安心感"的买卖，不是每天都要用的工具。

### 乔治·卢卡斯给自己造了一座博物馆

洛杉矶新开了一座卢卡斯叙事艺术博物馆，乔治·卢卡斯和他太太 Mellody Hobson 花了十七年才建成，光盖 LA 这一栋就用了八年。最近读到一篇逛展记，开头的画面让我停了一下：巨大的《星球大战》飞船模型，跟弗里达·卡罗的自画像挂在同一个展厅里。逛展的人抛出的问题很重——一个八十二岁的创作者，花一辈子造了这么多被亿万人热爱的"叙事艺术"，等他走后，这些东西怎么办？他自己的名声、他的遗产、他这个人，又怎么办？

让我停下来的是那个判断：卢卡斯想用两种方式回答"死后会怎样"这个人类最古老的问题。一种，带你看完整个视觉叙事的来龙去脉，看别人怎么处理创造与死亡；另一种，把他自己的作品——绝地武士、C-3PO——堂而皇之地摆进梵高、穆夏、弗里达·卡罗这些"正典"大师中间。逛完五个小时，你几乎被说服：他确实属于那里。

有一个细节我特别在意。博物馆是两翼结构，一边是细长的"北翼"（大厅、剧场、叙事艺术史的首展），一边是圆形的"教育翼"（图书馆、公共花园）。建筑从进门之前就在告诉观众：这趟旅程的主题是"平衡"。整个馆里所有东西都以"成对的对立"出现——流行对高雅、熟悉对陌生、高消费对亲民。策展人没打算模糊流行与高雅的界线，而是坚持：卓越的天赋和伟大存在于每一个层级，每一层的领头人都配得上被承认。

结尾那一句让我有点感慨：走出博物馆时，最强烈的冲动是立刻把《星球大战》原版重看一遍，然后自问——"这是不是意味着他赢了？"这是整篇最诚实的一刻。一座博物馆想证明的，从来不是展品多珍贵，而是"这些东西配得上被记住"。卢卡斯赌的是让观众用脚投票、用钱包投票，他赢了太多次，所以敢再赌一次。这篇逛展记叫[《乔治·卢卡斯花了17年造出他的最新世界，这一座你可以走进去》](https://bigthink.com/history-society/inside-the-lucas-museum-of-narrative-art/)，我本来对这类"富豪给自己建纪念馆"的新闻没什么兴趣，看完却觉得，这更像一个创作者在跟"死"做一次很具体的谈判。

### 你真的是你以为的那个人吗

Lisa Feldman Barrett 有个让我惦记了很久的说法：脑子里"我是谁"这个问题，其实问错了。真正能回答的，是"你在这一刻是谁"。她举的例子很生活化——一个喜欢打断别人说话的人，觉得自己"投入、热情"，急着把对方还没说完的话接上；但被打断的那个人，感受到的却是"粗鲁"。那这个人到底粗不粗鲁？她的答案是：都真实。不是被打断者的感受更重要，而是两种感受同等重要。

这个结论背后是一个叫"关系实在论"（relational realism）的立场：我们认为内在于一个人的那些特质，其实并不内在于那个人。它们是在"这个人和其他条件的关系"里才存在的。你熟人多、睡饱了、在饭局上，可能很外向；换个满是陌生人的房间、又饿着肚子，就未必。用她的话说，"描述你的是高度情境化的"。作为一个人，她承认这个想法让她别扭；但作为科学家，她说这看起来才是对的。

最触动我的，是她顺下来的那个推论。既然"我是谁"一部分是从互动里浮现的，那别人其实也在参与塑造我是谁——反过来，我也在参与塑造别人。这比听起来更重：我们对别人的身份，负的责任比我们以为的多；别人对我们"此刻是谁"，施加的影响也比我们愿意承认的多。这句话让我想起最近常跟 AI 协作的状态——当我把一个 prompt 写得更耐心、更具体，它回应的那个"人格"就更好；某种意义上，我也是在塑造那个回应我的"它"是谁。

她给女儿上大学的建议，我记了很久：去找那些"让你能成为最好版本的自己"的人。别去找让你舒服的人，去找让你成为那个人的人。这篇访谈收在 Big Think 和 Unlikely Collaborators 合作的《关系实在论》系列里，标题就叫[《你真的是你以为的那个人吗？》](https://bigthink.com/perception-box/are-you-really-who-you-think-you-are/)。我原来以为"你是谁"是个向内探索的问题，看完才发现，它一半答案在别人身上。

### 韦伯望远镜找到了最"失败"的恒星

天文学里有个词我一直觉得挺残忍：brown dwarf，棕矮星，中文更直白，叫"失败的恒星"。它们有恒星的样子，但质量不够，核心点不着氢聚变，一生都在慢慢冷却。最近韦伯望远镜在英仙座的 IC 348 星云里，找到了几个创纪录的小家伙——其中一对质量只有木星的两倍，是迄今已知最轻的棕矮星。

有意思的是这个"轻"到底轻到了什么程度。理论上，棕矮星的质量下限大约是木星的 13 倍，低于这个数，连氘（一种更轻的核聚变）都点不着。可这次找到的东西，质量只有木星 2 倍，比"理论上应该能存在的最轻棕矮星"还要轻一个量级，却偏偏像棕矮星一样发着红外光。换句话说，它们"不该存在"，但就在那儿。研究团队自己都说，这可能是一类全新的天体。

这类发现让我想到的，不是天文学，是"分类"这件事本身有多脆弱。我们给天体画了一条"恒星/行星"的界线，然后自然界随手塞进来一个跨在界线上、两边都不归的对象，整套分类就尴尬了。2023 年同一个团队在 IC 348 里找到过 3-4 倍木星质量的家伙，已经把"13 倍木星"这条理论下限敲松了；现在 2 倍木星的又来了。天文学里所谓的"记录"，常常不是答案，是"我们之前的模型漏了什么"。

这篇科普叫[《在一个巨大的恒星形成星云里，JWST 找到了最小的失败恒星》](https://bigthink.com/starts-with-a-bang/star-forming-nebula-jwst-smallest-failed-stars/)，配图那张十亿像素的星云拼图本身就很震撼。我看这类"打破纪录"的天文新闻，以前只当数字游戏；这次却觉得，"失败的恒星"这个说法本身可能就带着人类中心主义的傲慢——它没有失败，它只是没按我们的剧本点火。
