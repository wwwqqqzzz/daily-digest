### 蜂蜜几乎永远不会坏

蜂蜜是少数几乎不会变质的食物。考古学家在古埃及法老的墓里发现过密封的蜂蜜，三千多年后打开，依然可以食用。这不是民间传说，是有出土实物的记录。

原因在于蜂蜜的化学性质：含水量极低（约 17%），细菌和霉菌没法在这种干燥环境里繁殖；加上天然酸性（pH 3.2 到 4.5），以及蜜蜂分泌的葡萄糖氧化酶产生的微量过氧化氢，等于给微生物设了三重关卡。

有意思的地方在于，"能永久保存"这件事恰好来自蜂蜜的高度浓缩——蜜蜂把花蜜里近八成的水分蒸发掉，才得到这种几乎无菌的糖浆。人类花了上千年才发明罐头和冰箱，而蜜蜂早就用"脱水 + 酸化 + 抗菌酶"这套组合，做出了自然界最早的长效防腐方案。

### Plurai Simulation

> [!abstract] 简介
> 给 AI agent 造一个仿真世界：让它在上线前，先在数字孪生里被成千上万个"难缠用户"折磨一遍。

Plurai 做的事，是把自动驾驶那套"先在虚拟世界里跑几十亿英里再上路"的逻辑，搬到了 AI agent 上。你用 Claude Code、Codex 或 Copilot 里的一条命令，就能给 agent 生成一个数字孪生：合成的用户画像和文档、mock 掉的工具和 API、永不碰到生产环境的沙箱。它发现 agent 的失败、搞清楚为什么失败，再把失败变成补丁和训练数据，去微调专用的模型。

这个品类现在很挤：Langfuse、Confident AI、Basalt、Cekura 都在做 agent 评估。Plurai 的差异在于它不止"评"，还"修"——评估完直接后训练底层模型，形成"模拟 → 修复 → 再训练"的闭环。团队公布的几个数字挺硬：开发周期从几个月压到几小时，82% 的失败被拦在真实用户之前，成本降 97%。

它刚拿了 1300 万美元种子轮（Team8 领投），创始人是两位博士。诚实的边界也清楚：这更适合已经有生产级 agent、又因为隐私合规没法拿真实客户数据去测的企业——个人开发者玩票的话，门槛可能有点高。目前免费起步。

### Omnigraph

> [!example] 简介
> 给 AI agent 用的开源图数据库：多个 agent 共享同一份知识，写操作像代码一样有分支、可审查、能回滚。

Omnigraph 是一个开源的图数据库，专为"多个 AI agent 同时读写同一份知识"这个场景设计。它不跑在独立服务器上，而是把每个图存成开放的 Lance 格式，放在本地磁盘或任何 S3 兼容的对象存储里——存储便宜，数据也完全攥在自己手里。最特别的是它的版本控制：图像代码一样用分支管理，agent 和人都可以在分支上改，审查通过再合并回主干。

作者是 Modern Relay 的 Roman Pronskiy，从九月开始做，用 Rust 写成、MIT 协议，GitHub 上已经有 1,753 颗星。定位很清楚：替代 Neo4j、TigerGraph、Mem0，让"agent 记忆、公司知识图谱、上下文图谱"不用再自己拼一套存储层。

诚实地说，它现在还在早期，属于"给有基础设施能力的团队"的工具。但"统一的图 + 向量 + 全文检索在一条查询里"这个设计，加上版本化写入，确实是当前 agent 记忆类产品里少见的方向。

### ⌘+L

> [!info] 简介
> 一行脚本标签，让你像改 Figma 文件一样改自己的网站。

⌘+L（Command L）来自 Letter.dev，核心是一个"魔法脚本标签"：往网站里插一行，之后你就能像编辑 Figma 一样直接编辑这个网页。改动在后台由 Claude Code、Codex 或 Letterpress-1 自动变成一个干净的 pull request，而不是直接推上线。

### 我们造了座自己看不懂的数学大厦

Strogatz 和 Townsend 提出了一个词叫 Big Math——不是指哪道具体的难题，而是我们今天活在其中、却已经看不懂的那套数学。他们有一句话让我停了很久："我们不知道为什么这些模型这么好用。没有人知道。"

更细一点说，"我们懂它们由什么构成，懂它们经历的机制，懂学习过程——但我们不懂它们是怎么学到那些东西的。"懂零件，不懂整体。这句话不只是说 AI，说的是整个现代世界：你的短视频推荐、Netflix 把几个 T 的视频压成几个 G、苹果的 Find My 帮你定位手机、亚马逊的物流调度——拆开来全是数字，可这些数字背后运行的秩序，已经超出任何单个人的理解范围。

这让我想到一个有点反直觉的地方：数学曾经是人类用来理解世界、把复杂变简单的工具，现在它反过来变成了一座我们亲手搭起、却没人能俯视全貌的大厦。数学家自己也成了这座大厦里的一层住户，而不是总设计师。

他们还澄清了一个大众误解。媒体总爱描绘孤独天才关起门来啃十年难题，但 Townsend 说那根本不是大多数数学家的日常——真正的数学是高度协作的、社交的活动，绝大多数论文都有很多合作者。这也算一种安慰：连数学这么"纯粹"的领域，都是靠人堆出来的。

对我个人来说，这段 [Strogatz 和 Townsend 谈 Big Math 的访谈](https://bigthink.com/history-society/big-math/) 戳中的不是技术，是那种"我们已经生活在超出个人理解的结构里"的感觉。以后我再用那些好用到说不清原理的工具时，可能不会再去纠结"我为什么看不懂它"，而是接受这个事实：看不懂，不等于不能用，也不等于不值得用——只是我们这一代人，恰好站在了"理解"和"使用"第一次彻底脱节的位置上。

### 科学里的理论不是猜的

Ethan Siegel 反复在讲一个词和它被滥用的方式：theory。日常口语里，"理论"约等于"猜想、猜测、一个没证实的想法"。但有人把这个日常含义，套到了进化论、大爆炸、引力、量子力学这些科学理论上，说它们"只是理论"，所以不该被当成事实。

他还举了那些被当证据的例子：燃素说、荣格心理学、拉马克的用进废退，或者像大统一理论、弦理论这样名字里带"理论"的推测。用这些来论证"理论随时会被推翻，所以今天的共识也不可信"，逻辑上有个偷换——把"曾经被推翻的猜想"和"经过检验的稳固理论"混为一谈。

让我在意的是他给出的那个区分标准：一个真正的科学理论，不是"最后的终极答案"，但它是我们目前为止，用来理解这个宇宙最好、最成功的方式。把这种成功，和某人没受过训练的随口一猜划等号，是对人类文明这件事本身的侮辱。

这对我有个很具体的提醒。平时我会随手说"这只是个理论"——比如看到一个产品的增长假设、一个团队的做事方式。但现在我会多想一层：那个说法到底是我在表达"我不确定"，还是在用一个廉价的词，把一个经得起检验的东西抹掉？前者是诚实，后者是偷懒。

他还留了个尾巴：科学里确实也有"弦理论"这种名不副实的用法，"理论"这个词的歧义，一部分就来自这里。区分的关键从来不是名字，而是它下面有没有一堆通过检验的预测和证据撑着。这篇 [Ethan Siegel 谈科学里"理论"的含义](https://bigthink.com/starts-with-a-bang/never-tell-scientist-just-a-theory/) 写得很干净，适合在别人抛出"进化论只是理论"时转发过去。
